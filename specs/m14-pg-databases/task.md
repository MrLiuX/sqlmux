# M14 PG 数据库层级 · 任务清单

- **状态**：**draft**（2026-10-11 用户规划时定方向，排在 M13 之后）。
- **目标**：PG 的树从 连接 → schema 改成 连接 → 数据库 → schema，同 DataGrip；SSH 隧道；query 的上下文提示与值补全（用户后续补充的编辑体验需求也归到这里）。
- **范围**：tech-design §5（`Conn` 按数据库分 Meta / Main）、§7.8（树）、§8（`pg_database`）、§14（connections.toml 的 ssh 字段）。
- **依赖**：M13 passed。
- **审查节点**：待定（F14.1 单独一批；F14.2–F14.3 一批）。

已定的方向（2026-10-11，用户同意）：

- **F14.1 数据库层级**：PG 一个连接只能看一个库，所以每个数据库一对 `Meta` / `Main`，展开时才连；DSN 里的库默认展开；列表来自 `pg_database`（排除模板）。MySQL 不变（它的 database 就是 schema 这一层），SQLite 没有这一层。这是 M5 以来最大的模型改动，单独一个里程碑。
- **F14.2 SSH 隧道**：connections.toml 的 `ssh = "user@host"`（走本机的 ssh agent 和 `~/.ssh/config`），连接时先开隧道。终端用户多数自己 `ssh -L`，优先级低于 F14.1。

- **F14.3 query 的编辑体验：上下文提示与值补全**（用户 2026-10-11：INSERT 的 VALUES 里不知道第几个值对应哪个字段、什么类型，DataGrip 有字段名 hint；同类的编辑体验优化都归到这一条，用户 2026-10-11 定排到 M14，后续体验到的编辑体验问题和需求也补进这一条）。做法定为「签名提示加值补全」，不做行内虚拟文本（列号映射的代价，以后单独评估）：
  - **签名提示**：光标在某个「列上下文」里时，光标所在行的上一行（第一行时是下一行）画一条浮层，列出相关字段和类型，当前字段高亮、两边变暗，放不下只显示当前字段前后几个、两头 `…`；光标移动跟着换，出了上下文就消失，不用唤起也不用关；`[query] hints = false` 关掉。上下文：`INSERT … VALUES (…)`（按语句里的列清单，没写列清单按 catalog 的列顺序；第几个值按括号深度 1 的逗号数，字符串和注释里的不算，多行 VALUES 每个括号重新计数；`INSERT … SELECT` 不提示）；`UPDATE … SET col = `（这一列的名字和类型）；`WHERE` / `ON` / `HAVING` 里 `col = ` / `IN (` 的右边（这一列）；用户定义的函数的调用括号里（名字加参数签名，来自 catalog，和 M13 F13.3 的 Functions 节点同一份数据；内置函数不做，没有 catalog）。
  - **值补全**：在上面这些位置弹补全：枚举列列出枚举值（带引号）、布尔列 `true` / `false`、可空列 `NULL`、有默认值的列 `DEFAULT`（只在 INSERT / UPDATE 里）、时间列 `now()` / `CURRENT_TIMESTAMP`，和单元格编辑的选项浮层用同一份 catalog 数据；其余列照旧不弹。
  - **同类小项**（一起做）：`INSERT INTO t ` 后补全时提供 `(全部列) VALUES ()` 的骨架（光标停在括号里）；`UPDATE t SET` 后的列补全只列这张表的列；补全插入的标识符需要引号时加引号（去掉 §12「已知上限」里的那一条）。
  - 候选但没定（用户补充后加）：`SELECT` 列表里 `*` 展开成全部列名；悬停或 `K` 看光标下标识符的类型和注释。
